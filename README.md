# 안심ON - 나와 닮은 돌봄 유형검사

졸업전시(LG 스탠바이미 2세대 · 세로 · 터치)용 정적 웹사이트입니다. HTML/CSS/Vanilla JS만 쓰고, 외부 CDN이나 네트워크 없이 동작합니다.

## 파일 구조

```
index.html          화면 틀
style.css           모든 스타일 (Figma 1080×1920 좌표 그대로)
script.js           질문·결과 데이터 / 점수 계산 / 화면 전환 / 로딩 애니메이션
assets/
  fonts/            Pretendard 400·500·600·700·800 (woff2)
  img/
    logo.png            안심ON 로고 (흰 배경을 투명 처리) — 모든 화면 좌측 상단
    start-illust.png    시작 화면 메인 일러스트
    char-1.png          결과 TYPE 01 책임온 캐릭터
    char-2.png          결과 TYPE 02 채점온 캐릭터
    char-3.png          결과 TYPE 03 포착온 캐릭터
    char-4.png          결과 TYPE 04 같이온 캐릭터
    sil-1~4.png         로딩 화면 회색 실루엣 (같은 캔버스를 4등분)
    load-1~4.png        로딩 화면 완성 캐릭터 (실루엣과 같은 좌표로 4등분 → 외곽 정확히 일치)
```

## 실행·배포

- 로컬 확인: 폴더에서 `python3 -m http.server` 실행 후 `http://localhost:8000` 접속
  (index.html을 더블클릭해도 대부분 동작하지만, 폰트 때문에 서버 실행을 권장)
- GitHub Pages: 이 폴더 내용을 저장소 루트에 올리고 Settings → Pages → Branch `main` / `/(root)` 선택. 모든 경로가 상대 경로라 그대로 동작합니다.

## 개발 모드

URL 뒤에 `?debug=1`을 붙이면 왼쪽 아래에 뷰포트 크기, devicePixelRatio, 배율, 현재 질문, 응답, 유형별 점수, 동점 여부, 결과가 표시됩니다.

바로가기(개발 모드에서만):
- `?debug=1&q=3` → Q3 화면 (`q=7`은 추가 질문 — 응답이 없으면 4유형 모두 동점이라 카드 4개가 보임)
- `?debug=1&screen=loading` → 로딩 애니메이션
- `?debug=1&result=resp` (`judge` / `catch` / `together`) → 결과 화면

## 점수 규칙 (2026-10-26 새 질문 기준)

| 질문 | A | B | C | D |
|---|---|---|---|---|
| Q1 | 책임온 | 채점온 | 포착온 | 같이온 |
| Q2 | 포착온 | 채점온 | 책임온 | 같이온 |
| Q3 | 같이온 | 포착온 | 책임온 | 채점온 |
| Q4 | 포착온 | 책임온 | 같이온 | 채점온 |
| Q5 | 책임온 | 포착온 | 같이온 | 채점온 |
| Q6 | 채점온 | 책임온 | 포착온 | 같이온 |
| Q7 | 책임온 | 채점온 | 포착온 | 같이온 |

- 선택지 하나당 해당 유형 +1점, Q1~Q6만 합산 (Q7은 점수에 넣지 않음)
- 최고점이 하나면 Q7 없이 바로 로딩 → 결과
- 최고점이 2개 이상 같으면 FINAL QUESTION(Q7) 표시
  - 최고점 동점 유형의 카드만 보여주고, 알파벳은 보이는 순서대로 A, B, C…
  - 고른 유형이 최종 결과
  - 카드가 2개면 설명이 시안대로 "둘 다", 3개 이상이면 "모두"
- 최고점이 아닌 유형끼리 같은 점수인 것은 Q7 조건이 아님
- Q1~Q6 답을 바꾸면 Q7 선택은 초기화되고, 동점이 풀리면 Q7을 건너뜀

4,096가지 응답 조합 전부에서 동점 판정과 결과가 규칙과 일치하는 것을 확인했습니다.

## 확인이 필요한 부분 (임시로 처리한 것)

새 질문 시안에 있는 다음 부분은 오타일 수 있지만 시안 그대로 넣었습니다: Q7 제목 앞 공백, Q7 B 문장 끝 마침표 없음, Q2 B '진행되고,  그'의 두 칸 띄어쓰기, Q3 D 앞 공백, Q3 선택지의 단어 중간 줄바꿈(주/의할, 지/금은, 빠/짐없이, 수/리). Q6 설명의 '7시/로' 줄바꿈도 시안 그대로입니다.

| 항목 | 현재 처리 | 바꾸는 곳 |
|---|---|---|
| 선택지 선택 상태 디자인 ('질문 선택 시 화면' 시안 미전달) | 연하늘 배경 + 남색 테두리 + 남색 원/흰 글자 | `style.css`의 `--sel-*` 변수 |
| '다음' 비활성 상태 | 투명도 0.3 | `--disabled-opacity` |
| 폰트 | Pretendard로 추정해 적용 | `--font-base` |
| "Q1." 번호 폰트 | 시안은 다른 둥근 고딕으로 보여 Pretendard ExtraBold로 임시 적용 | `--font-qnum` + `@font-face` 추가 |

## 스탠바이미 실기 테스트 항목

1. `?debug=1`로 열어 실제 뷰포트 크기와 devicePixelRatio 확인
2. 브라우저 전체 화면에서 위·아래 여백 없이 꽉 차는지 (9:16이 아니면 위·아래에 같은 색 여백이 생김)
3. 선택지·이전·다음·처음으로 버튼이 한 번 터치에 반응하는지
4. 화면을 빠르게 연속 터치해도 화면이 겹치거나 두 번 넘어가지 않는지
5. 로딩에서 캐릭터가 왼쪽부터 한 명씩 나타나고 실루엣과 어긋나지 않는지
6. 결과 화면이 맨 위에서 시작하고 손가락으로 부드럽게 스크롤되는지, 가로 스크롤이 없는지
7. 결과 화면의 '처음으로'로 돌아가 다시 검사할 때 이전 응답이 남아 있지 않은지
8. 처음 접속할 때 글자가 늦게 바뀌지 않는지 (폰트 로딩)
